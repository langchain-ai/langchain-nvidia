# Non-text NIM modality gaps (EMBUAHFQ-960)

**Maintainer proposal, not implemented support or a compatibility claim.** The current package exports chat/completions, embedding, reranking, and RAG search clients, but no OCR, page-layout/table-structure, or ASR client ([exports](../langchain_nvidia_ai_endpoints/__init__.py#L46-L69)). Its registered client/model types are limited to those existing routes ([model schema](../langchain_nvidia_ai_endpoints/_statics.py#L46-L105)); Doctor checks only chat, embeddings, completions, and ranking via `/models`, not inference for these modalities ([Doctor](../langchain_nvidia_ai_endpoints/_doctor.py#L19-L25), [README](../README.md#L74-L91)). Do not treat a VLM image prompt, chat reply, model-listing result, or historical registry entry as OCR, layout, table, or speech support. Verify any proposed client against the *specific* deployed NIM and its API version before advertising it.

## NVIDIA API contracts and proposed fit

| Category | Documented request and response | Gap and recommended LangChain fit |
| --- | --- | --- |
| Image OCR | [Image OCR NIM API](https://docs.nvidia.com/nim/ingestion/image-ocr/latest/api-reference.html#extract-text-data-from-image): `POST /v1/infer` with JSON `input: [{"type":"image_url","url":"data:image/png;base64,..."}]` (PNG or JPEG), optionally one `merge_levels` value per image (`word`, `sentence`, `paragraph`; default paragraph). `data` has image `index` and `text_detections` with `text_prediction.text`, `text_prediction.confidence`, and `bounding_box.points` (normalized x/y); `usage.images_size_mb` is reported. | No OCR request/response adapter. Propose an **image-to-Document loader/parser**, with recognized text in `page_content` and source, image index, text confidence, and normalized polygons in metadata; retain the raw detections for callers needing geometry. A chat VLM's `image_url` conversion is not an OCR API ([VLM conversion](../langchain_nvidia_ai_endpoints/chat_models.py#L189-L245)). |
| Page elements | [Object Detection NIM API](https://docs.nvidia.com/nim/ingestion/object-detection/latest/api-reference.html#compute-bounding-boxes): same `POST /v1/infer` JSON base64 PNG/JPEG image-array input, against a **page-elements deployment**. `data[index].bounding_boxes` maps detected labels (examples include `table`, `chart`, `title`, `paragraph`, `header_footer`) to boxes with `x_min`, `y_min`, `x_max`, `y_max`, `confidence`; `usage.images_size_mb` is reported. | No layout-detection adapter. Propose a typed layout result preserving label, confidence, coordinates, image index and source; an optional downstream Document conversion can use these as metadata, but bounding boxes alone are **not** extracted text. The deployment/model determines the labels; do not promise the example label set universally. |
| Table structure | The same [Object Detection NIM API](https://docs.nvidia.com/nim/ingestion/object-detection/latest/api-reference.html#table-structure-example), against a **table-structure deployment**, accepts a base64 PNG/JPEG image array at `POST /v1/infer` and demonstrates table `cell`, `row`, and `column` boxes. It uses the documented `data[index].bounding_boxes` structure (box coordinates and confidence), not ready-made Markdown/HTML or cell text. | No table-structure adapter. Propose a typed geometry result; preserve image index, source and cell/row/column coordinates and confidence. Defer table-text assembly to an explicit composition with OCR and, when processing full pages, page-elements detection/cropping. Do not imply OCR alone reconstructs tables or that table geometry alone supplies cell text. |
| Offline ASR | [Speech NIM HTTP API](https://docs.nvidia.com/nim/speech/latest/reference/api-references/asr/http-asr.html#post-v1-audio-transcriptions): `POST /v1/audio/transcriptions` uses **multipart/form-data** `file` (WAV, OPUS, FLAC), plus `language` (BCP-47) or `model`; `model` takes precedence. Optional `response_format=json` yields `{"text":"..."}`; `response_format=text` yields plain text. Missing both language and model, unsupported response format, or unknown model return 400 `{"detail":"..."}`; an unready NIM returns 503. | No audio upload or transcript adapter. Propose an **offline audio-to-Document loader/parser** with transcript in `page_content` and source plus explicitly provided language/model in metadata. Do not invent timestamps, diarization, or speaker information from this HTTP response. HTTP audio **translation** is a separate model-dependent route, and [streaming/realtime uses gRPC or WebSocket](https://docs.nvidia.com/nim/speech/latest/reference/api-references/asr/index.html), not this HTTP transcription client. |

[LangChain document loaders](https://docs.langchain.com/oss/python/integrations/document_loaders) provide `load`/`lazy_load` into `Document`; this is the proposed abstraction for extracted text, **not a present package feature**. Keep structured image results available without flattening them into misleading prose. Existing connector requests post JSON to fixed inference paths ([transport](../langchain_nvidia_ai_endpoints/_common.py#L472-L493), [embeddings](../langchain_nvidia_ai_endpoints/embeddings.py#L150-L161), [ranking](../langchain_nvidia_ai_endpoints/reranking.py#L225-L231)); it neither implements multipart ASR nor a general `/v1/infer` parser. Its generic response aggregation selects `data[0]` for non-chat responses ([parser](../langchain_nvidia_ai_endpoints/_common.py#L625-L668)), which would discard additional image results. Do **not** solve this by registering OCR/layout/ASR IDs as `ChatNVIDIA` or by simply swapping the chat endpoint. A self-hosted NIM `/v1/infer` is a route relative to *that NIM's* root; don't assume hosted Catalog routing or authentication are identical. Existing `NVIDIARAGRetriever` is `/v1/search` against a RAG server, not an ingestion adapter ([retriever](../langchain_nvidia_ai_endpoints/retrievers.py#L70-L99)).

## Implementation choices and validation contract (future work)

Select **OCR**, **page-elements + table-structure** (two separately configured deployments under one layout/geometry initiative), and **offline HTTP ASR** for follow-up implementation. Sequence OCR and layout independently; make composition an explicit, separately verified use case. Scope ASR to the documented offline HTTP transcription mode. Keep all four **unknown/unavailable** as connector capabilities until their adapters and deployed endpoint behavior are demonstrated; no registry capability or BCB badge should be inferred from this proposal ([registry provenance](model_registry.md#schema-version-1), [compatibility evidence](compatibility.md#reading-the-view)).

1. **Input fixtures / boundaries:** deterministic, tiny PNG and JPEG data URLs, two distinct images, and an invalid MIME/base64 fixture; assert exact `input` order, image MIME, and OCR `merge_levels` length and accepted values. For ASR, use tiny WAV/OPUS/FLAC fixtures and inspect multipart `file` plus language/model precedence, without embedding audio bytes in JSON or logs. Explicitly reject unsupported PDF-as-image, arbitrary remote image URL, or other file types unless a particular adapter has intentionally documented preprocessing. No real credentials in fixtures.
2. **Output parsing:** OCR two-image response in *reversed index order* with multiple detections, distinct text/confidence/polygons: verify all indexed results survive and text maps to the right source. Page-elements response with two labels and multiple boxes and table-structure response with cell/row/column boxes: verify exact category/coordinate mapping and empty valid detection lists. Preserve normalized geometry; don't turn layout boxes into purported OCR text or hallucinate table cell content. ASR JSON `text` and explicitly requested plain-text mode must yield the transcript exactly, including empty transcript handling; neither should run through the chat `choices`/embedding parser.
3. **Errors and metadata:** malformed/missing `data`, duplicate/out-of-range image indexes, malformed polygon/box coordinates, invalid confidence, malformed ASR JSON/missing `text`, HTTP 400/401/413/503 and timeouts must be surfaced with actionable errors, not empty success. Test source, image/page index when supplied, per-detection confidence and boxes, merge level, and actual provider `usage.images_size_mb` preservation without claiming token usage or timestamps. Use a fake HTTP transport for fixture tests and a deployment-specific, opt-in smoke test for each real endpoint, recording deployed model/version and observed request/response shape separately from model catalog availability.
4. **Unsupported modes:** ensure chat streaming/tools, embeddings/reranking, realtime ASR (gRPC/WebSocket), audio translation, PDF ingestion, and automatic table-to-text reconstruction are *not* advertised or silently routed via these adapters. Requests for unimplemented modes should fail clearly before an inference request. Existing Doctor and the reviewed registry should continue to mark these unverified until their own modality-aware checks and provenance are separately implemented.

## Draft implementation tickets

- **NVIDIA Image OCR NIM document extraction adapter:** add a separately configured `/v1/infer` image-to-Document client. Accept base64 PNG/JPEG and optional per-image merge levels; preserve every indexed text detection, confidence, normalized polygon, source, and reported image-size usage. Acceptance: two-image reversed-index and malformed-response fixtures, HTTP errors, unsupported PDF/remote-image modes, plus an opt-in deployment-specific smoke before advertising support.
- **NVIDIA Page Elements and Table Structure geometry adapters:** implement separately configured `/v1/infer` clients with typed boxes and labels, preserving source, image index, confidence, and normalized geometry. Acceptance: multiple labels/boxes, table cell/row/column mapping, empty detections, invalid coordinates and indexes, HTTP failures, and an opt-in smoke for each deployment. OCR composition and table-text reconstruction require separate evidence; neither is included.
- **NVIDIA Speech NIM offline HTTP transcription loader:** send WAV/OPUS/FLAC files to multipart `/v1/audio/transcriptions`; preserve the exact JSON/plain-text transcript, source, and supplied language/model selection. Acceptance: language/model precedence, empty transcript, malformed responses, 400/401/413/503 and timeout handling, clear rejection of realtime/translation modes, plus an opt-in deployment-specific smoke before support is claimed.
